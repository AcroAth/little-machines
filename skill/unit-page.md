# Unit page — process, principles, and earned rules

This book compiles source material into hand-crafted interactive lesson pages — "explorable explanations, industrialized." The author's standing rule is **quality first**: the bar is *"could this sit inside Mathigon without embarrassment; would Nicky Case recognize the spirit."* Generic-but-polished is a failure mode. Every rule below was earned in a real review round; the catalog exists so the same defect never costs a round twice.

## Authority documents (read before acting; never duplicate them, reference them)

| Document | What it owns |
|---|---|
| `design/reference-analysis.md` | The quality bar: Mathigon grammar, Case formula, shared DNA, anti-slop gates |
| `design/north-star-spec.md` | The book's design tokens/motion/typography (BPE page, the north star) |
| `design/language-modeling-spec.md` | The current best template for a unit spec's structure |
| `design/book-plan.md` | Curriculum: chapters = source-lecture order; concepts anchor at first appearance |
| `JOURNAL.md` | Chronological truth: every decision, round, and lesson with its date |

This skill is the **single canonical home of the earned rules** — new unit specs reference it ("all rules in the unit-page skill apply") and carry only unit-specific art direction, instead of restating the catalog.

## The pipeline (roles: a design lead designs and reviews; a builder implements; the author judges)

1. **Read the source.** The unit's concept page — produced by a separate ingestion pipeline from the source material — plus the transcript segments its citations point at. The concept page is the content authority; this book derives all pedagogy itself — the only contract with the ingestion pipeline is format stability.
2. **Write the unit spec** (`design/<unit-id>-spec.md`), following the section structure of `language-modeling-spec.md`: concept · design-system inheritance (one line pointing here) · the page's own instrument(s) · gated beats · footnotes/sources · engineering constraints · acceptance gates · out of scope. The spec is where design happens — never skip to building. State the palette *thesis* (how the book's three hues map to this unit's story), the fidelity boundary, and every prerequisite the reader needs stated (acronyms expanded, numbering explained).
3. **Brief the build** to a capable builder at high effort (this is the craft-critical path — don't under-provision). The brief lists: the spec, the DNA source page to copy tokens from, the source + transcript paths, both deliverable paths (`<unit-id>.html` + `<unit-id>-build-notes.md`), the hard rules, and the requirement to self-verify every acceptance gate headlessly and report deviations.
4. **Adversarial review** (non-negotiable — builders' self-checks have missed 10 defects in a single page). Protocol below.
5. **Ship for review.** Serve the page locally over HTTP and review it in rounds; keep the same file path stable for the unit's lifetime. Version labels: `round-N-<slug>`. Favicon stays fixed per unit.
6. **Author review rounds.** Fix sub-threshold findings directly (mechanical string/logic edits — the round-5 precedent); re-delegate larger rework. Verify every fix live before republishing.
7. **Record.** Update `JOURNAL.md` (every milestone, same day) and the unit's build notes (append each round). New rules earned in a round get added to THIS skill.

## Design principles (the book's DNA)

- **The subject itself is directly manipulable** — the reader drags the token, pours the belief, walks the timeline. Never a control panel beside a picture of the thing.
- **Pace is authored.** Gated beats (`section.beat[data-beat]`, hidden until goals fire), a hairline progress rail, `Reveal all steps` escape valve, `~N min` disclosed. The page must complete naturally from a hard reload without the escape valve. Reveals are *felt*: beats enter with the book's fade+rise (`rise` .9s; reveal-all staggers 90ms) and **must fade even under reduced motion** (`fadeReveal` .45s — an instant pop is a defect; reduced-motion readers got pops for the book's whole first month, 2026-07-24 round). Every page carries the **frontier cue**: hand-lettered `the page continues when you play` + three breathing dots, trailing the last revealed beat and retiring once nothing is hidden. The cue WHISPERS — 1.05rem, words in `--ink2`, only the dots gold (author review round 2026-07-24: full-gold cue was indistinguishable beside gold instrument annotations; one hand-lettered register per role — annotations own loud gold, the page-edge cue speaks in ink). Exact tokens/lifecycle: north-star-spec §4; rationale: `design/reveal-motion-cue-spec.md`.
- **Play before terminology.** The cold open is the experience itself; names arrive after the reader has already done the thing. Wonder-first, second person, light humor, lean prose — the instruments carry the teaching. This applies to *choices* too: an option the page will argue for is EARNED mid-page, never offered before it's taught (unit 3's "multiplied" bet confused the author sitting untaught beside the rumor's two answers; it now appears only in the final re-pour, as "the answer the rectangle just put on the table").
- **Prose and figures are one fabric.** Inline blanks, draggable numbers, and target-pointers live inside sentences; hand-lettered gold notes point into instruments; captions sit on the column axis.
- **A designed identity per book.** Copy the design tokens **verbatim** from the current DNA page (`@font-face` data-URI, full `:root` + dark + `data-theme` blocks, shared idiom classes) — verify with a diff/md5, don't retype. Palette roles for "Language, from scratch": **byte blue** = the mechanical/possible · **token vermilion** = the resolved/meaningful · **invitation gold** = the reader's touch ONLY · green = goal ticks only. No other hues; Patrick Hand for annotations only; system-ui body 18px/1.65 in a 40rem column.
- **Characters, not widgets.** Instruments with personality are the book's soul (the UNK blob, the little machine). Drawn inline-SVG ink creatures — expressions via eyes/posture, squash-stretch reactions ≤320ms. Keep them small and shy; the author responds to character moments — keep investing in them. Anatomy follows the creature's own geometry: one lid per eye shaped like the eye, never one slab across the face (unit 3's rectangular nap-lid read as "a rectangle on its face" — the author). **The cast registry `book/cast/` documents every character** (anchors, expression vocabulary, canon rule); the pages remain canon — port byte-identical from the canonical page it names. **The canonical machine is the-bitter-lesson's lidded variant** — language-modeling's `machineSVG()` has no lid elements (its `.blink` CSS is dead code there; its idle loop flashes `think` as a workaround — don't reproduce the mismatch).
- **Honesty contract.** Every number the reader sees is real — a genuine count/measurement from data the page names, or a quantity the reader placed. Nothing invented, no placeholder data, no fake precision. If an embedded model/corpus powers an instrument, the page says what it is.
- **Silence, absolutely.** No audio APIs ever. Motion is the warmth channel; full `prefers-reduced-motion` path (fades only; static affordances replace wiggle/gesture-hand).
- **Fidelity boundary.** Every historical/definitional claim traces to the source concept page or transcript — no invented years, names, numbers, or mechanisms (codegen's known failure). The game/characters/metaphors are the book's own devices and assert nothing. Named figures get only what the source says. Build-notes must include a claim→anchor table.
- **The reader has no computer-science background** (the author, 2026-07-23 — the author is the first reader). The book's only prerequisites are its own earlier pages. Trade names and initialisms are UNK blobs to this reader: at first appearance, expand the short form ("LSTMs — short for Long Short-Term Memory"), translate it into plain words ("a vector" → "one short list of numbers"; "kernels" → "the small programs that run on them"), or at minimum give category plus a familiar anchor ("two models named ELMo and BERT"; "GPT-2 — an early ancestor of today's chatbots"). A term the book teaches in a later chapter gets a promise ("you'll meet it properly later in this book"), and never gets used as working vocabulary before its chapter — the guessing-game page says "what comes next", not "the next token", because tokens are the next chapter's story. Expanding a name is not a fidelity violation; describing an unsourced mechanism is. The Sources block may keep the lecture's own terms — it is provenance, not teaching.

## Mistakes to avoid (the earned-rules catalog — each cost a real round)

**Reader-surface hygiene**
- No dashboard grammar, ever: cards, borders-around-prose, stat tiles, pill chips, numbered kickers, default-styled form controls, emoji in UI, cream+teal-by-default. (The original sin — both prototypes rejected as "extremely AI slop.")
- No project-internal labels on the page ("hand-crafted", "silent by design", build meta). Header meta = reading time + Reveal-all only; a Sources block ends the page.
- No intra-page hash links — they fight gating (an early defect: a citation superscript navigated and lost page state). Footnote superscripts are plain non-interactive flags. Never pin a claim to a timestamp that doesn't support it (a page-level statement cites "this page").
- No unglossed initialisms or terms of art anywhere in reader prose — LSTM, ELMo, BERT, "vector", "kernels", "feedforward" all shipped unexplained once and the author (correctly) read them as UNK blobs. Sweep with a caps-pattern grep before review; tick/place-name labels may stay short only if the caption the reader reaches translates them.
- **Course/source names are provenance, never identity** (the author, 2026-07-24: the project is "a very nicely decorated notebook for things that I learn" — not limited to CS336). "CS336" / "Language Modeling from Scratch" and source-shaped structure (chapter counts pinned to a syllabus — "Seventeen more chapters"; "one chapter per lecture") never appear in reader-facing framing: titles, headings, intros, footers, taglines. They live only in Sources blocks and honesty-contract corpus statements ("the machine read one lecture — the Stanford CS336 opening" stays). Frame growth open-ended ("More chapters follow"), so the copy survives new sources and re-planning. (Contents page carried all three violations; de-coursed in its round 2.)

- **An unlabeled abstract mark reads as a page defect, and a channel that decorates what is FINE to imply what is broken inverts the reader's question.** Round 7's seam view underlined the *real* stretches and dropped a bare gold nick at the first seam — the author: "Is that a crack? …the underlines increased my confusion." Hand-drawn glyphs earn intent through pictorial character (eyes) or words (the gold notes); a floating stroke has neither. When the finding is "show me where X breaks," prefer making the subject PERFORM its failure (round 8: the babble line itself steps downhill at each seam) over annotating provenance around it.

**Layout and annotation**
- Only the instrument itself may exceed the column (up to ~52rem, `min()`-clamped, self-centered); its content centers on the column axis; captions/status return to the column's left edge.
- Drawn arrows: shaft stops 4–5px short of the head's apex, approaches along the barbs' bisector, ≥2px centerline clearance from both barbs — audit programmatically.
- An arrow must point at the actual thing at every width, in every state. Annotation units are non-wrapping and anchored. A hint under a *centered* row must itself center (left-anchored hint + centered row = arrow into empty space — this exact bug shipped twice in different forms).
- A character's speech aside anchors BESIDE its speaker, inside the speaker's own layout band — a fixed below-the-character offset escapes the band and collides with neighbors at short viewports (cover round 1, 2026-07-24: the blob's aside landed on the title at ≤480px).
- Any host that renders candidate words/tiles gets the row grammar (wrapping flex row, bottom-aligned) — a bare div stacks block-level flex children into a ragged column and misaligns their underlines.

**Interaction**
- Linked representations stay live: if two views show the same state, changing either updates the other (merges AND undos, lever AND babble). **Corollary: adding a new representation of shared state re-opens this audit for every OTHER view of that state.** Beat 5 had silently shown a stale roll after beat-4 rerolls for its whole life; the moment round 7's underlines made the two lines comparable word-for-word, the staleness became a visible lie beside "watch the same roll fall apart" (LM round 7, 2026-07-24 — fixed with a writer-side refresh hook: every finished roll re-renders the other view, not just the view's own controls).
- Feedback lands where the reader is looking: actions with off-screen effects scroll first, then glow ≥1.8s after the scroll settles, with an empty-target fallback.
- Every gesture gets an affordance or a one-time hand-lettered hint. Nothing undiscoverable, nothing nagging. Scrubbable things look grabbable (pill/underline/cursor); no chevrons (the author: ugly).
- **An idiom ports WITH its fix history.** Any `pointerdown` handler that calls `preventDefault()` suppresses native focus — it must call `.focus()` itself or click-then-keyboard dies (fixed in BPE round 1, re-shipped in unit 2 by copying the idiom without the fix).
- Check shared-class styling across every consumer — a `.lit` styled for `.tile` but not `.vtile` is a silent no-op.
- Every revealed round completes its sentence: if a stem has a gap, the reveal fills it (beat 1 set the pattern; beats that skip it feel unfinished).
- A character's reaction is a moment, not a state: every non-idle expression sets a timed path back to idle (cleared if the next action starts early). Idle-only ambient loops never rescue a stuck expression. A *conditional* reset is the same bug wearing a guard — the timer must land unconditionally on the current context's resting face (unit 3: a reset gated on "still at the frontier" stranded the machine surprised at the laptop).
- Displayed quantities are denominated in what the reader can watch the mechanic do. (A "memory of 3 words" lever driving a trigram that conditions on 2 contradicted the page's own sandbox.) **Corollary — one slot, one denomination:** a display slot the reader watched a mechanic write (the number under a belief bar = drops they poured) must mean the same thing everywhere it appears; reusing it for a different unit is a silent lie the reader catches ("Number: 21, description: 6 of its 10" — unit 1 showed lecture *counts* in the *drops* slot, 2026-07-24). Counts and other second denominations go into prose, explicitly denominated ("followed with it 21 times").
- **A revealed control always has a live action.** Hide "play the next round" when no round remains — a button that can only do nothing teaches the reader not to trust buttons (unit 1, 2026-07-24).
- **A verdict that names the reader compares BOTH sides' numbers.** The honesty contract covers sentences, not just displayed quantities: "you beat it" is a claim about the reader's state and must be computed from it, never canned. (Unit 1's beat-3 verdict said "you beat it" off the machine's argmax alone while the reader's pour on the true word was lower — the author: "Did I beat it? I don't think so", 2026-07-24.)
- Choice blanks are authored correct-first in source (the `[[correct|wrong|wrong]]` convention) — the renderer MUST deal presentation order with the shared seeded `mcShuffle(menu, blankEl.id)` idiom (FNV-1a of `id + ":mc1"` seeding xorshift32 Fisher-Yates, re-append; the salt is book-wide — changing it re-deals every blank in every unit). Every dropdown in the book rendered the answer first until the author's full-motion pass caught it (2026-07-23). Audit: no blank renders correct first; correct's position varies across a page's blanks; `opts` captured only after the shuffle.

**Accessibility**
- Keyboard + touch + mouse for every interaction; `aria-live` on changing content; visible focus; AA contrast both themes (gold-on-light is AA-large display-only — documented, don't widen its use).
- Audit every **goal's** input path for keyboard specifically — instrument-level keyboard checks miss prose-level interactives. (Round 7: the target-pointers were bare click-only spans while g5 required touching one, locking keyboard readers out of beat 6 for six straight review rounds. Any element with a click handler that feeds a goal gets `role="button"` + `tabindex="0"` + Enter/Space.)
- If a visual structure carries sentence content and is `aria-hidden`, provide the sentence to screen readers (`.sronly` span).

**Engineering**
- Fragment file: `<meta charset="utf-8">` first, one `<style>`, content, one `<script>`. No doctype/html/head/body. Zero external resources; fonts as data URIs; vanilla JS + inline SVG. ≤300KB. Works as a raw local file AND as a hosted static page.
- Seeded RNG for anything generative (same seed → same output; re-roll = new seed). Prune embedded data to budget — never fake it to fit.
- Console clean from hard reload through full natural playthrough AND reveal-all + instrument-poking.
- **Entrance animations drop their classes on `animationend`.** Retained `both` fill keeps the animation applied forever, which makes every revealed beat a stacking context — popover z-indexes (`.menu` z:20) get trapped inside and paint UNDER later-DOM transformed content (the frontier cue overlapped an open dropdown, 2026-07-24). The document-level cleanup listener (removes `reveal-anim`/`fade-in`/`cue-in` when `rise`/`fadeReveal` end) is part of the reveal idiom — port it with the idiom.
- **Reader-typed text enters the DOM only via `textContent`/`createTextNode` — never string-concatenated into `innerHTML`.** `innerHTML` templates are for constant markup and fixed embedded data only. A shared tile/vocab renderer is reachable through whichever caller has the loosest input, even when most callers only ever pass it fixed corpora: bpe-north-star's `tileHTML`/`render`/`addVocab` (fed by the free-sandbox `#corpusEdit`) and the encode beat's tile builder (fed by `#encodeEntry`) all built tiles by concatenating `vis(tokenText(tok))` straight into `innerHTML` — `vis()` maps whitespace/control characters to display glyphs but passes `< > &` through raw, so typing `<img src=x onerror=...>` into either field executed script (self-XSS, caught in review, 2026-07-24). Audit every `innerHTML=` assignment in a page for reachability from ANY reader-editable input, however indirect the path (corpus → byteSeq → tokens → tokenText/vis); fix by building the span with `document.createElement`+`textContent` and appending badge/id spans as sibling nodes — never reach for a hand-rolled escaper when the DOM API already escapes for you.

## Verification protocol

**Builder self-verifies (gates go in the spec, results in build notes):** honesty gate (extract embedded tables/engine in Node; re-derive every displayed number), fidelity table (every claim → anchor), first-viewport playable at 1280×800 and 375×812, gating end-to-end, anti-slop grep sweep (`href="#`, audio APIs, external URLs, default controls, emoji), interaction matrix (mouse/touch/keyboard × every instrument), arrow-geometry audit, both themes, reduced motion, size + console, honest feel-check. Anything unverifiable gets flagged loudly, never silently passed.

**Adversarial review (after every build — assume the self-checks missed things):**
1. Rebuild any embedded data independently from the raw source with your own script; diff against what shipped.
2. Read the full page (style, body, script). Check every prose claim against the source; check every displayed-quantity denomination against the mechanic; check idiom fix-history (focus, shared classes, gap-fills).
3. Live playthrough in a real browser: natural progression from hard reload (no escape valve) to full rail; then reveal-all path; wrong-answer paths; determinism checks; backoff/edge inputs; both themes; 375px; console.
4. Watch for common browser-automation pitfalls before trusting a live check: stale screenshot coordinates after a reload, synthetic key events that don't match real key names, JS probes that steal focus, and navigation that opens a new tab while an old one is still referenced — always confirm you're driving the tab you think you are.
5. **A round built around a NEW visual grammar gets a rendered look-check (screenshot, any theme) before it ships.** Round 7 sim-validated every number and shipped the underline+mark grammar unseen; it failed on first sight (an author review round, 2026-07-24). Data validation is not design validation. If you can't render it live, say so in the notes and treat the author's pass as the visual gate — but never *skip* the attempt.
6. Distinguish real defects from float-tie/tooling artifacts before "fixing" them (a largest-remainder tie broken by float jitter is valid; a stale a11y tree showing hidden beats is a tooling artifact, not the page). Trust outcomes over tool renderings.

Ship only after the honesty and fidelity gates pass. After author rounds: verify each fix live, re-ship with a new `round-N` label, and append the round to build notes and the journal.

## Growing the book

- Sequence follows the source (author rule): next units come from `book-plan.md` order, not preference. A concept anchors at its first source lecture; later deepenings become "revisited" cross-references.
- **The book is one shelf of a larger notebook** (the author, 2026-07-24): the project will hold learning beyond CS336. `book-plan.md`'s lecture-order spine stays an internal organizing principle (a book's spine is its source's own order) — never a reader-facing identity claim. Future non-CS336 sources join as new chapters or new books; name books for their subject ("Language, from scratch"), never for their source course.
- Cross-page references in UNIT pages are plain text — units don't link each other yet. The book's front door exists (cover 📖 → contents 🗺️ → units; spec `design/cover-contents-spec.md`). Links ship `target="_blank"`+`rel="noopener"` (correct as local files and on the real host). On GitHub Pages the contents page is the map and every unit page is a direct link.
- When a round teaches a new rule, add it to this catalog in the same commit as the fix, and note it in the journal entry. The catalog only grows from evidence.
